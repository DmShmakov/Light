# Мобильное приложение (PWA) для фитнес-студии

**Версия:** 1.1

---

## 1. Введение

### 1.1. Назначение документа
Настоящий документ определяет требования к разработке мобильного приложения для фитнес-студии на платформе Android. Приложение предназначено для автоматизации процесса записи клиентов на занятия и предоставления удобного интерфейса для просмотра расписания.

### 1.2. Цели проекта
- Упростить процесс записи клиентов на занятия
- Предоставить клиентам актуальную информацию о расписании и доступных местах
- Автоматизировать административные процессы управления расписанием
- Повысить лояльность клиентов через систему уведомлений

### 1.3. Целевая аудитория
- Клиенты фитнес-студии (основные пользователи)
- Администраторы студии (управление расписанием и записями)

---

## 2. Общие требования

### 2.1. Платформа
- **Тип приложения:** Progressive Web App (PWA)
- **Фреймворк:** React + TypeScript (рекомендуется) или Vue.js
- **Сборка:** Vite
- **UI-библиотека:** Material UI / Tailwind CSS + Headless UI
- **Адаптивность:** Mobile-first подход, поддержка всех современных мобильных браузеров
- **Минимальные требования:**
  - Android: Chrome 80+ (2020 г.)
  - iOS: Safari 13+ (2019 г.)
  - Desktop: Chrome, Firefox, Safari, Edge (последние 2 версии)

**Преимущества PWA:**
- ✅ Работает на Android и iOS из коробки
- ✅ Установка на домашний экран без App Store/Google Play
- ✅ Офлайн-режим через Service Workers
- ✅ Push-уведомления (Android + Desktop)
- ✅ Быстрая разработка и деплой
- ✅ Нет комиссий магазинов приложений
- ✅ Единая кодовая база для всех платформ

### 2.2. Бэкенд (рекомендация)
- **Firebase** (рекомендуется для первого этапа):
  - Firebase Authentication — авторизация
  - Firestore Database — хранение данных
  - Firebase Cloud Messaging (FCM) — push-уведомления
  - Firebase Storage — хранение изображений (при необходимости)
  - Firebase Crashlytics — мониторинг ошибок

**Преимущества Firebase:**
- Быстрая интеграция
- Не требуется выделенный сервер
- Автоматическое масштабирование
- Бесплатный тариф для небольших проектов

### 2.3. Роли пользователей

**Важно:** Один пользователь может совмещать несколько ролей одновременно. Например, администратор одновременно является и клиентом (может записываться на занятия).

| Роль | Описание |
|------|----------|
| **Гость** | Незарегистрированный пользователь (только просмотр расписания) |
| **Клиент** | Зарегистрированный пользователь (запись на занятия, просмотр информации) |
| **Администратор** | Управление расписанием, просмотр списков записавшихся |

**Примечание:** Роли "Клиент" и "Администратор" не исключают друг друга. Администратор имеет все права клиента плюс права управления.

## 3. Функциональные требования

### 3.1. Модуль авторизации и регистрации

#### 3.1.1. Быстрая регистрация
**Описание:** Пользователь может быстро зарегистрироваться в приложении.

**Способы регистрации:**
1. **По email** — ввод email → получение письма с кодом/ссылкой → подтверждение
2. **Через Google аккаунт** — один тап для входа через Google

**Требования:**
- Обязательные поля: имя, номер телефона
- Опционально: фото профиля, дата рождения, предпочтения по занятиям
- Автоматический вход после регистрации
- Возможность выйти и войти повторно

**Дополнительно (Фаза 2):**
3. **Через VK ID** — авторизация через аккаунт ВКонтакте
4. **Через Яндекс ID** — авторизация через аккаунт Яндекса

**Реализация OAuth провайдеров (Фаза 2):**
- **VK ID:** Прямая интеграция через OAuth 2.0
  - Документация: https://id.vk.com/
  - Endpoint: `https://id.vk.com/oauth/v2`
  - Создание приложения в VK Developers
- **Яндекс ID:** Прямая интеграция через OAuth 2.0
  - Документация: https://yandex.ru/dev/oauth/doc/dg/concepts/about.html
  - Endpoint: `https://oauth.yandex.ru/`
  - Создание приложения в Яндекс OAuth
- Firebase Authentication с Custom Tokens для объединения аккаунтов
- Промежуточный сервер (Firebase Cloud Functions) для обмена кода на токен

#### 3.1.2. Авторизация
- Сохранение сессии между запусками приложения
- Автоматический вход при повторном открытии (если сессия валидна)
- Возможность выхода из аккаунта

#### 3.1.3. Восстановление доступа
- Для email: ссылка для сброса пароля/кода
- Для Google: перепривязка аккаунта

### 3.2. Модуль просмотра расписания

#### 3.2.1. Отображение расписания
**Описание:** Пользователь может просматривать расписание ближайших занятий.

**Функционал:**
- **Представление по неделям:** Расписание отображается в виде недельных блоков. Для записи доступны ближайшие **2 недели** от текущей даты.
- **Недели доступны для записи:** Настройка в админ-панели (по умолчанию: 2 недели). Пользователи с ролями Гость и Клиент могут просматривать и записываться только на занятия в пределах этого периода.
- **Календарный вид:** Отображение занятий в виде списка по дням недели с указанием даты
- **Фильтры:**
  - По типу занятия (йога, пилатес, кроссфит и т.д.)
  - По тренеру
  - По времени (утро/день/вечер)
  - По уровню сложности (начальный/средний/продвинутый)
- **Поиск:** По названию занятия или имени тренера
- **Сортировка:** По дате, по времени, по популярности

#### 3.2.2. Карточка занятия
**Информация:**
- Название занятия
- Дата и время начала/окончания
- Имя тренера
- Тип/уровень занятия
- Описание занятия (краткое)
- Количество свободных мест (например: "Свободно: 5 из 15")
- Статус (доступно для записи / мест нет / идёт сейчас / закончено)
- Фото/аватар тренера (опционально)

**Действия:**
- Кнопка "Поделиться" — копирование ссылки на занятие для публикации во внешних ресурсах (мессенджеры, соцсети)

### 3.3. Модуль записи на занятие

#### 3.3.1. Просмотр информации о занятии
**Перед записью пользователь может видеть:**
- Полную информацию о занятии (из 3.2.2)
- Количество свободных мест (например: "5 записано из 15")
- Свой статус (записан / не записан)

**Важно:** Обычные пользователи (роли "Гость" и "Клиент") **НЕ видят** список других участников занятия. Эта информация доступна только администраторам.

#### 3.3.2. Запись на занятие
**Процесс:**
1. Пользователь нажимает кнопку "Записаться"
2. **Проверка авторизации:** Если пользователь не авторизован (роль "Гость") — перенаправление на экран регистрации с сообщением "Для записи на занятие необходима регистрация"
3. Подтверждение записи (диалог: "Вы уверены, что хотите записаться?")
4. Успешная запись → обновление интерфейса, показ уведомления
5. Если мест нет → показ уведомления "Мест нет, хотите встать в очередь?"

**Ограничения:**
- **Гость (неавторизованный пользователь) не может записаться на занятие — требуется предварительная регистрация**
- Нельзя записаться на занятие, которое уже прошло
- Нельзя записаться на занятие, которое начинается менее чем через X минут (настраивается)
- Лимит одновременных записей (опционально, например, не более 3 занятий в день)

#### 3.3.3. Отмена записи
- Пользователь может отменить свою запись
- Кнопка "Отменить запись" доступна до **X минут** до начала занятия (по умолчанию: **60 минут**, настраивается в приложении)
- Подтверждение отмены (диалог)
- Освобождение места происходит мгновенно
- Если до занятия осталось менее установленного времени — отмена невозможна, показывается сообщение: "Отмена возможна не позднее чем за X минут до начала занятия"

#### 3.3.4. Лист ожидания (опционально для будущего)
- Если мест нет, пользователь может встать в очередь
- При освобождении места — автоматическое уведомление
- Первый в очереди получает приоритет

#### 3.3.5. Deep Links (глубокие ссылки)

**Описание:** Пользователь может скопировать ссылку на конкретное занятие и поделиться ею через внешние ресурсы (мессенджеры, соцсети).

**Формат ссылки:**
- URL: `https://yourstudio.app/class/{classId}`
- Пример: `https://yourstudio.app/class/yoga-20260415-1800`

**Поведение при переходе по ссылке:**
1. **Приложение установлено:**
   - Автоматическое открытие приложения
   - Переход на экран деталей занятия с фокусом на конкретном занятии
   - Если пользователь не авторизован — показ экрана авторизации с последующим переходом к занятию
2. **Приложение не установлено:**
   - Переход на страницу приложения в Google Play (fallback)
   - Опционально: веб-страница с информацией о занятии

**Реализация:**
- Web Share API + копирование в буфер обмена
- PWA нативно поддерживает URL маршрутизацию
- При переходе по ссылке — автоматическое открытие PWA с нужным экраном
- Поддержка всех мобильных платформ (Android/iOS)

### 3.4. Модуль уведомлений (Push-уведомления)

#### 3.4.1. Типы уведомлений
| Тип | Когда отправляется | Получатели |
|-----|-------------------|------------|
| Напоминание о занятии | За 2 часа до начала | Записанные участники |
| Изменение расписания | При изменении/отмене занятия | Записанные участники |
| Освобождение места | При отмене кем-то записи | Пользователи в листе ожидания |
| Подтверждение записи | Сразу после записи | Пользователь |
| Административные | Новые записи, изменения | Администраторы |

#### 3.4.2. Настройка уведомлений
- Пользователь может включить/отключить уведомления
- Выбор типов уведомлений (опционально)

### 3.5. Административный модуль

#### 3.5.0. Связь с администратором
**Описание:** Пользователи с ролями Гость и Клиент могут отправить сообщение администратору студии.

**Доступ:**
- Роли: Гость, Клиент
- Доступно из профиля пользователя или экрана расписания

**Функционал:**
- Отправка текстового сообщения администратору
- Выбор темы обращения (вопрос по расписанию, проблема с записью, общее предложение и т.д.)
- История отправленных сообщений с статусом (отправлено, прочитано, получен ответ)
- Push-уведомление администратору о новом сообщении
- Возможность получения ответа от администратора (push-уведомление + просмотр в приложении)

**Ограничения:**
- Лимит сообщений (например, не более 5 в день — настраивается)
- Защита от спама (интервал между сообщениями: минимум 1 минута)
- Неавторизованный пользователь (Гость) должен оставить контактные данные (email или телефон) для ответа

#### 3.5.1. Доступ администратора
- Отдельная роль в системе (назначается вручную через Firebase Console или первый админ создаёт других)
- Вход через те же способы авторизации, но с проверкой роли
- Админ-панель доступна только пользователям с ролью "Администратор"

#### 3.5.2. Управление расписанием

**Создание занятия:**
- Название занятия
- Тип/категория
- Дата и время начала/окончания
- Тренер
- Максимальное количество участников
- Описание
- Повторяемость (разовое/ежедневно/еженедельно — опционально)

**Редактирование занятия:**
- Изменение любого поля
- Отмена занятия (с автоматической рассылкой уведомлений записанным)
- Изменение количества мест

**Удаление занятия:**
- С подтверждением
- С уведомлением всех записанных участников

**Просмотр расписания:**
- Все занятия (прошедшие и будущие)
- Фильтры по дате, тренеру, типу занятия
- Быстрое редактирование (inline)

#### 3.5.3. Просмотр записавшихся

**Список участников занятия:**
- Имя участника
- Контактные данные (телефон/email)
- Дата и время записи
- Статус (подтверждён/отменён)
- Возможность удалить участника из записи (с уведомлением)

**Статистика по занятию:**
- Общее количество записавшихся
- Количество свободных мест
- Количество отмен

#### 3.5.4. Управление пользователями (базовое)
- Просмотр списка всех пользователей
- Поиск по имени/телефону/email
- Просмотр истории записей пользователя
- Блокировка пользователя (опционально)

## 4. Структура данных (Firestore)

### 4.1. Коллекции

#### `users` — Пользователи
```
{
  "uid": "string",              // Уникальный ID (Firebase Auth)
  "name": "string",             // Имя пользователя
  "email": "string|null",       // Email
  "phone": "string",            // Телефон (ОБЯЗАТЕЛЬНО)
  "photoUrl": "string|null",    // URL фото профиля
  "roles": ["client", "admin"], // Массив ролей (пользователь может совмещать)
  "createdAt": "timestamp",     // Дата регистрации
  "preferences": {              // Предпочтения (опционально)
    "favoriteTypes": ["yoga", "pilates"],
    "notificationsEnabled": true
  }
}
```

#### `classes` — Занятия
```
{
  "classId": "string",          // Уникальный ID занятия
  "title": "string",            // Название
  "type": "string",             // Тип (йога, пилатес...)
  "trainerId": "string",        // ID тренера (из users)
  "trainerName": "string",      // Имя тренера (денормализация)
  "startDateTime": "timestamp", // Начало
  "endDateTime": "timestamp",   // Окончание
  "maxParticipants": "number",  // Макс. количество мест
  "description": "string",      // Описание
  "level": "beginner|intermediate|advanced",
  "status": "scheduled|cancelled|completed",
  "createdAt": "timestamp"
}
```

#### `enrollments` — Записи на занятия
```
{
  "enrollmentId": "string",     // Уникальный ID записи
  "classId": "string",          // ID занятия
  "userId": "string",           // ID пользователя
  "enrolledAt": "timestamp",    // Время записи
  "status": "confirmed|cancelled",
  "waitlistPosition": "number|null"  // Позиция в очереди (если есть)
}
```

#### `admin_messages` — Сообщения администратору
```
{
  "messageId": "string",        // Уникальный ID сообщения
  "senderId": "string|null",    // ID отправителя (null для гостей)
  "senderName": "string",       // Имя отправителя
  "senderContact": "string",    // Email или телефон для ответа
  "subject": "string",          // Тема обращения
  "message": "string",          // Текст сообщения
  "createdAt": "timestamp",     // Время отправки
  "status": "sent|read|replied",// Статус сообщения
  "adminResponse": "string|null", // Ответ администратора
  "adminResponseAt": "timestamp|null" // Время ответа
}
```

#### `app_settings` — Настройки приложения
```
{
  "scheduleWeeksAvailable": 2,  // Количество недель для записи (по умолчанию: 2)
  "cancellationDeadlineMinutes": 60, // Минимальное время до занятия для отмены (минуты)
  "maxMessagesPerDay": 5,       // Лимит сообщений администратору в день
  "messageSpamIntervalMinutes": 1 // Минимальный интервал между сообщениями
}
```

## 5. Правила безопасности (Firestore Security Rules)

### 5.1. Пользователи
- Чтение: авторизованные пользователи могут читать только свой профиль и публичные данные других (имя, фото)
- Запись: пользователь может редактировать только свой профиль
- Администраторы имеют полный доступ

### 5.2. Занятия
- Чтение: все (включая неавторизованных) могут просматривать расписание
- Запись: только администраторы

### 5.3. Записи
- Чтение: пользователь видит свои записи; админ видит все
- Создание: авторизованные пользователи могут записываться
- Удаление/изменение: только владелец записи или администратор

## 6. Нефункциональные требования

### 6.1. Производительность
- Загрузка расписания: не более 2 секунд при хорошем соединении
- Плавность анимаций: 60 FPS
- Кэширование данных для офлайн-доступа (последние 7 дней)

### 6.2. Офлайн-режим
- Просмотр кэшированного расписания без интернета
- Отображение статуса подключения
- Автоматическая синхронизация при восстановлении связи

### 6.3. Безопасность
- Все данные передаются по HTTPS
- Токены авторизации хранятся безопасно (EncryptedSharedPreferences)
- Валидация данных на клиенте и сервере (Firestore Rules)

### 6.4. Поддержка экранов
- Смартфоны (минимальная ширина: 360dp)
- Планшеты (опционально, рекомендуется для админ-панели)
- Поддержка портретной и ландшафтной ориентации

### 6.5. Локализация
- Основной язык: Русский
- Дополнительно: Английский (опционально для будущего)

## 7. Экраны приложения

### 7.1. Экраны авторизации
1. **Экран приветствия** — выбор способа входа/регистрации
2. **Экран входа** — email + пароль или Google
3. **Экран регистрации** — форма быстрой регистрации (email + телефон обязательны)
4. **Экран восстановления доступа** — сброс пароля/кода

### 7.2. Основные экраны клиента
5. **Главный экран (расписание)** — список занятий, фильтры

7. **Мои записи** — список предстоящих занятий пользователя
8. **Профиль** — данные пользователя, настройки, выход

## 13. Ограничения и допущения

1. **Интернет-соединение:** Большинство функций требуют подключения к интернету (есть базовый офлайн-режим через Service Worker)
2. **Push-уведомления на iOS:** Ограничены в PWA — работают только при открытом приложении (ограничение Safari)
3. **Firebase:** Бесплатно до ~50K чтений/день, ~20K записей/день
4. **Администраторы:** Назначаются вручную (нет самостоятельной регистрации как админ)
5. **Валидация:** Firestore Security Rules обеспечивают безопасность на сервере
6. **Конфиденциальность:** Пользователи **НЕ видят** других записавшихся. Список участников видят только администраторы.
7. **OAuth провайдеры:** Требуется создание приложений в VK Developers и Яндекс OAuth
8. **PWA ограничения:** 
   - На iOS некоторые функции ограничены (background sync, полный доступ к устройству)
   - Push-уведомления на iOS поддерживаются частично (iOS 16.4+ при установке на домашний экран)
