# Техническая документация: Модуль тренеров (Trainer Module)

**Версия:** 1.0  
**Дата:** 22 апреля 2026 г.  
**Статус:** Концепция (не реализован)

---

## 1. Обзор

Модуль тренеров вводит роль `trainer` в систему ролей приложения и предоставляет тренерам персональный раздел для работы со своими занятиями. Тренер может просматривать список своих занятий, видеть кто на них записался, и получать уведомления о событиях в своих занятиях.

### 1.1. Ключевые возможности

- Роль `trainer` как отдельная роль пользователя (не конфликтует с ролью `admin`)
- Назначение тренером только пользователей с ролью `trainer` при создании/редактировании занятия
- Раздел «Мои занятия» — список занятий тренера с навигацией по неделям
- Просмотр списка участников на каждое занятие тренера
- Уведомления: назначение на занятие, запись/отмена участников, изменение и отмена занятия, напоминание перед началом

### 1.2. Роли и их комбинации

| Роль | Описание |
|---|---|
| `client` | Обычный пользователь — запись на занятия |
| `trainer` | Тренер — ведёт занятия, видит своих участников |
| `admin` | Администратор — управляет расписанием, пользователями, абонементами |
| `['admin', 'trainer']` | Тренер-администратор — полный доступ плюс персональные занятия |

## 2. Изменения в модели данных

### 2.1. `UserRole`

```typescript
// Текущее состояние
type UserRole = 'client' | 'admin'

// После реализации
type UserRole = 'client' | 'admin' | 'trainer'
```

### 2.2. Коллекция `users`

Добавление роли происходит через существующее поле `roles: string[]`. Никаких дополнительных полей в документе пользователя не требуется.

Для выборки тренеров (в форме создания занятия) запрос:

```
collection('users').where('roles', 'array-contains', 'trainer')
```

### 2.3. Коллекция `classes`

Поле `trainerId: string` уже присутствует в типе `FitnessClass` и в схеме Firestore. В текущей реализации оно заполняется вручную через свободный текст `trainerName` и может не соответствовать реальному UID пользователя.

После реализации модуля тренеров:
- `trainerId` — всегда UID пользователя с ролью `trainer` (обязательное, выбирается из справочника)
- `trainerName` — денормализованное поле, заполняется автоматически из профиля выбранного тренера

| Поле | Тип | Изменение |
|---|---|---|
| `trainerId` | `string` | Был произвольной строкой → теперь всегда UID пользователя-тренера |
| `trainerName` | `string` | Заполняется автоматически из `user.name` при выборе тренера |

> **Миграция:** существующие занятия, у которых `trainerId` не является валидным UID, будут отображаться корректно (тренер не увидит их в «Моих занятиях»), но при редактировании администратору потребуется переназначить тренера из справочника.

### 2.4. `NotificationTypePreferences`

Добавляются три новых типа уведомлений, специфичных для тренеров:

```typescript
// Текущее состояние
type NotificationType =
  | 'enrollment_confirmed'
  | 'class_reminder'
  | 'class_changed'
  | 'class_cancelled'
  | 'waitlist_opening'
  | 'admin_notifications'

// После реализации
type NotificationType =
  | 'enrollment_confirmed'
  | 'class_reminder'
  | 'class_changed'
  | 'class_cancelled'
  | 'waitlist_opening'
  | 'admin_notifications'
  // Новые — только для тренеров
  | 'trainer_assigned'       // Назначен на занятие
  | 'participant_enrolled'   // Участник записался на занятие тренера
  | 'participant_cancelled'  // Участник отменил запись на занятие тренера
```

Тренерские типы уведомлений отображаются в настройках только пользователям с ролью `trainer`.

## 3. Изменения в административном интерфейсе

### 3.1. Форма создания/редактирования занятия

**Текущее состояние:** поле «Тренер» — свободный текст (`TextField`), `trainerName` сохраняется как строка, `trainerId` фактически не заполняется корректно.

**После реализации:** поле «Тренер» заменяется на `Autocomplete` со списком пользователей, у которых есть роль `trainer`. При выборе автоматически устанавливаются `trainerId` и `trainerName`.

```
Тренер *
┌────────────────────────────────────────┐
│ Иванова Мария                       ▼  │  ← Autocomplete
└────────────────────────────────────────┘
  Иванова Мария (maria@studio.ru)
  Петров Алексей (alex@studio.ru)
```

**Изменения в `classSchema`:**
```typescript
// Было
trainerName: z.string().min(2, 'Введите имя тренера'),

// Станет
trainerId: z.string().min(1, 'Выберите тренера'),
// trainerName заполняется автоматически — в schema не нужно
```

**Изменения при сохранении:** вместе с `trainerId`/`trainerName` отправляется Cloud Function уведомление `trainer_assigned` тренеру (при создании нового занятия или при смене тренера на существующем).

### 3.2. Управление пользователями (`/admin/users`)

В карточке пользователя добавляется возможность выдать/снять роль `trainer` (рядом с ролью `admin`). Добавление роли не удаляет другие роли — `roles` это массив.

### 4.3. Загрузка данных

```typescript
// Запрос занятий тренера за неделю
const q = query(
  collection(db, 'classes'),
  where('trainerId', '==', userId),
  where('startDateTime', '>=', weekStart),
  where('startDateTime', '<=', weekEnd),
  orderBy('startDateTime', 'asc')
)
```

Требует составного индекса Firestore (см. раздел 7).

### 4.4. Список участников

Кнопка «Участники» открывает `Dialog` со списком пользователей, записанных на занятие. Тренер видит имена и аватары — аналогично блоку «Записавшиеся» на `ClassDetailsPage` для администратора.

```
┌──────────────────────────────────────┐
│ Участники — Йога для начинающих   ✕  │
│ 22 апреля, 10:00                      │
├──────────────────────────────────────┤

│ 👤 Мария Козлова                      │
│    ... ещё 5                          │
└──────────────────────────────────────┘
```

**Источник данных:** `getEnrollmentsForClass(classId)` — та же функция, что использует администратор.

### 4.5. Доступ к списку участников через `ClassDetailsPage`

На странице деталей занятия (`/class/:classId`) блок «Записавшиеся» отображается:
- Если текущий пользователь — `admin`, **или**
- Если `fitnessClass.trainerId === user.uid`

Таким образом тренер видит участников своего занятия прямо на странице занятия без перехода в отдельный раздел.

## 5. Уведомления для тренеров

### 5.1. Типы уведомлений и триггеры

| Тип | Триггер | Кто отправляет | Получатель |
|---|---|---|---|
| `trainer_assigned` | Создание занятия / смена тренера на занятии | Cloud Function `onClassWrite` | Тренер занятия |
| `trainer_unassigned` | Смена тренера / удаление занятия | Cloud Function `onClassWrite` | Прежний тренер |
| `participant_enrolled` | Пользователь записался на занятие | Cloud Function `onEnrollmentCreate` | Тренер занятия |
| `participant_cancelled` | Пользователь отменил запись | Cloud Function `onEnrollmentUpdate` | Тренер занятия |
| `class_changed` | Изменились дата/время/детали занятия | Cloud Function `onClassWrite` | Тренер занятия |
| `class_cancelled` | Занятие отменено (`status = 'cancelled'`) | Cloud Function `onClassWrite` | Тренер занятия |
| `class_reminder` | За N часов до начала занятия | Cloud Function `scheduledReminder` | Тренер занятия |

### 5.2. Содержимое уведомлений

```
trainer_assigned:
  Заголовок: «Вы назначены тренером»
  Текст:     «Занятие: Йога, 25 апреля в 10:00»
  Действие:  переход на /class/:classId

trainer_unassigned:
  Заголовок: «Вас убрали с занятия»
  Текст:     «Занятие: Йога, 25 апреля в 10:00 назначено другому тренеру»

participant_enrolled:
  Заголовок: «Новая запись»
  Текст:     «Анна Смирнова записалась на Йога (22 апр, 10:00). Записано: 9/15»
  Действие:  переход на /class/:classId

participant_cancelled:
  Заголовок: «Отмена записи»
  Текст:     «Иван Петров отменил запись на Йога (22 апр, 10:00). Записано: 8/15»

class_changed:
  Заголовок: «Изменение в вашем занятии»
  Текст:     «Йога перенесена на 23 апреля в 11:00»

class_cancelled:
  Заголовок: «Занятие отменено»
  Текст:     «Йога 22 апреля в 10:00 отменена администратором»

class_reminder:
  Заголовок: «Ваше занятие начинается через 2 часа»
  Текст:     «Йога, 10:00 — 11:00. Записано: 9 участников»
```

### 5.3. Настройки уведомлений

В `NotificationSettingsPage` добавляется секция «Для тренеров», видимая только пользователям с ролью `trainer`:

```
Для тренеров
├── [✓] Назначение на занятие         (trainer_assigned)
├── [✓] Запись участника              (participant_enrolled)
├── [✓] Отмена участника              (participant_cancelled)
├── [✓] Изменение занятия             (class_changed)
├── [✓] Отмена занятия                (class_cancelled)
└── [✓] Напоминание перед занятием    (class_reminder)
```

По умолчанию все тренерские уведомления включены.

### 5.4. Cloud Function — изменения

Существующие функции расширяются новыми ветками:

**`onClassWrite`** — дополнительно к текущей логике:
```
При создании класса:
  → Найти trainerId → отправить trainer_assigned тренеру

При обновлении класса:
  → Если trainerId изменился:
      → trainer_unassigned → прежнему тренеру
      → trainer_assigned   → новому тренеру
  → Если изменились startDateTime / endDateTime:
      → class_changed → тренеру
  → Если status стал 'cancelled':
      → class_cancelled → тренеру
```

**`onEnrollmentCreate`** — дополнительно:
```
При создании enrollment (status = 'confirmed'):
  → Найти classId → получить trainerId → отправить participant_enrolled тренеру
```

**`onEnrollmentUpdate`** — дополнительно:
```
При статусе enrollment → 'cancelled':
  → Найти classId → получить trainerId → отправить participant_cancelled тренеру
```

**`scheduledReminder`** — дополнительно:
```
За N часов до занятия:
  → Отправить class_reminder тренеру занятия (+ count записавшихся)
```

## 6. Правила безопасности Firestore

### 6.1. Занятия (`classes`)

Тренер может читать занятия (уже разрешено правилом `allow read: if true`). Изменение занятий — только для администратора (без изменений).

### 6.2. Записи (`enrollments`)

Тренер должен иметь доступ к записям участников своих занятий. Текущее правило `allow read: if request.auth != null` уже обеспечивает это. В будущем, для более строгой модели, правило может быть расширено:

```javascript
match /enrollments/{enrollmentId} {
  allow read: if request.auth != null && (
    // Собственная запись
    resource.data.userId == request.auth.uid ||
    // Администратор
    isAdmin() ||
    // Тренер своего занятия
    isTrainerOfClass(resource.data.classId)
  );
  // ... create, update, delete без изменений
}

function isTrainerOfClass(classId) {
  return get(/databases/$(database)/documents/classes/$(classId))
    .data.trainerId == request.auth.uid
}
```

> **Примечание:** `isTrainerOfClass` выполняет дополнительный `get()` при каждой проверке. При высокой нагрузке рекомендуется денормализовать `trainerId` в документ `enrollment` (добавить поле `trainerId` при создании записи через Cloud Function).

### 6.3. Пользователи (`users`)

Без изменений — любой авторизованный пользователь может читать коллекцию пользователей (нужно для поиска тренеров в форме создания занятия).

## 7. Требуемые индексы Firestore

| Коллекция | Поля | Тип | Назначение |
|---|---|---|---|
| `classes` | `trainerId ASC`, `startDateTime ASC` | Composite | Запрос занятий тренера за неделю |
| `users` | `roles ARRAY` | Auto (single-field) | `where('roles', 'array-contains', 'trainer')` — создаётся автоматически |

## 8. Навигация

### 8.1. Нижняя навигация

| Вкладка | Маршрут | Видит |
|---|---|---|
| Расписание | `/` | Все |
| Мои записи | `/my-enrollments` | Клиент, тренер |
| **Мои занятия** | `/trainer/my-classes` | **Только тренер** |
| Профиль | `/profile` | Все |

Если пользователь является одновременно `trainer` и `client` (обычный сценарий — тренер тоже может записываться на чужие занятия), обе вкладки отображаются.

### 8.2. Защита маршрута

```tsx
// В App.tsx
<Route path="/trainer/my-classes" element={
  <TrainerRoute>
    <TrainerMyClassesPage />
  </TrainerRoute>
} />
```

`TrainerRoute` — аналог `ProtectedRoute`, дополнительно проверяет `user.roles.includes('trainer')`. При отсутствии роли — редирект на `/`.
